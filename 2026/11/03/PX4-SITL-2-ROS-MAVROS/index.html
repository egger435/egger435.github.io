从 PX4 SITL 到 ROS + MAVROS 外部控制

Posted on 2026-11-03 In 无人机学习 Views:

  无人机学习笔记：ROS + MAVROS 与 PX4 的外部位置控制

  在学习了ROS和MAVROS之后，需要从之前的Python + pymavlink的控制方式转向ROS + MAVROS控制方式。

什么是MAVROS，为什么需要它

  简单来说，MAVROS是连接ROS和MAVLink的桥梁。它运行在ROS中，将ROS的Topic/Sevivces转换成PX4能够理解的MAVLink消息。

  在Python ROS程序中使用ROS相关的消息、服务等机制，而在PX4中对外主要通过MAVLink。因此，如果想要将PX4接入ROS、通过ROS来控制无人机的话就需要MAVROS来负责中间的转换，这样就能够使用ROS生态中的大量工具和算法，起到提高开发效率的目的。

ROS、MAVROS和PX4的通信架构

ROS Python Node
       |
       | ROS Topic / Service
       |
     MAVROS
       |
       | MAVLink
       |
      PX4
       |
       | uORB
       |
 PX4 内部控制模块
       |
       |
     电机

  以上为概念上的简化结构。

名词 解释
ROS Node ROS 中独立运行的程序
ROS Topic 节点之间进行异步消息通信的机制
ROS Message Topic之间传输的一种数据结构
ROS Service 请求-响应式通信机制
MAVROS ROS 与 MAVLink 飞控系统之间的桥梁
MAVLink 无人机系统之间的通信协议
uORB PX4内部的消息发布与订阅机制

PX4 SITL和MAVROS建立通信

实验环境

  • Windows：Windows11
  • 虚拟环境：WSL2
  • Ubuntu：20.04
  • ROS：Noetic
  • PX4：v1.12.3
  • Gazebo：Classic 11.15.1
  • MAVROS：1.20.1

启动仿真与端口配置

PX4+Gazebo：

Tools/gazebo_sitl_multiple_run.sh -n 1 -m iris -w empty

MAVROS:

source /opt/ros/noetic/setup.bash

roslaunch mavros px4.launch fcu_url:="udp://:14540@127.0.0.1:14580"
端口 作用
14580 PX4本地发送端口
14540 MAVROS接收端口

通信验证

rostopic echo -n 1 /mavros/state
rostopic echo -n 1 /mavros/local_position/pose

坐标系：ENU与NED

ENU: + x: East + y: North + z: Up

NED: + x: North + y: East + z: Down

  ROS 偏向机器人和地面环境，因此常使用 ENU；PX4/MAVLink 源于航空导航体系，因此常使用 NED。二者使用上需要注意坐标系变换。

通过ROS Python节点监控PX4状态

订阅两个Topic：

/mavros/state
/mavros/local_position/pose

关键代码结构

rospy.Subscriber(
    "/mavros/state",
    State,
    self.state_callback
)

rospy.Subscriber(
    "/mavros/local_position/pose",
    PoseStamped,
    self.pose_callback
)

ROS回调函数

  当对应Topic收到消息时候触发回调函数，消息参数作为msg传入回调函数。

  需要注意的是：回调函数负责接收和保存数据，主循环负责按照自己的节奏处理数据。这样可以避免回调函数执行过久，影响整个ROS节点的运行

OFFBOARD模式与PX4控制机制

  OFFBOARD式PX4的外部控制模式，允许外部计算机通过MAVLink向PX4提供控制设定值

Setpoint与OFFBOARD的关系

  发布Setpoint不等于无人机执行Setpoint，PX4需要处于OFFBOARD模式，才会将符合要求的外部控制设定值作为控制目标。

频率要求

  • PX4 v1.12.3 要求外部控制信号至少 2 Hz。
  • 进入 OFFBOARD 前，需要提前持续发送 Setpoint。
  • 实际开发中常用 20–50 Hz。
  • 运行期间必须持续更新，不能长时间中断。

失联保护

  当 PX4 处于 OFFBOARD 模式时，如果长时间没有收到外部控制程序发送的有效控制指令，PX4 就会认为外部控制端失联，并触发预设的保护措施。

参数 作用
COM_OF_LOSS_T Offboard 失联后，等待多长时间再触发保护
COM_OBL_ACT Offboard 失联时的主要保护动作（无 RC 情况）
COM_OBL_RC_ACT Offboard 失联时存在 RC 遥控器情况下的保护动作
